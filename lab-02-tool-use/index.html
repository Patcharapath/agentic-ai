Tools และ agent loop: ตรวจใบแจ้งหนี้กับใบสั่งซื้อTools and the agent loop: checking invoices against purchase orders

ให้ LLM เรียก tools ที่เปิด PDF คำนวณยอด ค้นฐานข้อมูล และบันทึกผล แล้วเขียน agent loop เองGive the LLM tools that open PDFs, recalculate totals, query a database and save results, then write the agent loop yourself

70 นาทีใน class70 min in classต่อจาก Module 2Follows Module 2Core 6 ส่วน + Stretch (MCP)6 Core parts + Stretch (MCP)

ใบแจ้งหนี้ PDF 8 ฉบับรอการตรวจ แต่ละฉบับต้องตรวจว่ายอดรวมถูกต้อง และตรงกับใบสั่งซื้อ (purchase order, PO) ในฐานข้อมูลหรือไม่ แล้วบันทึกว่าอนุมัติหรือปฏิเสธ คุณจะให้ LLM ทำงานนี้ผ่าน tools และเขียน loop ที่ทำให้มันทำงานหลายขั้นต่อกันได้

เมื่อจบ lab คุณจะสามารถ

  • อธิบายได้ว่า model เห็นอะไรจาก tool และใครเป็นผู้รัน tool จริง
  • เขียน agent loop เองด้วย bind_tools, tool_calls และ ToolMessage
  • ออกแบบ tool ให้ model ใช้ผิดได้ยาก และคืน error ในรูปที่ model นำไปใช้ต่อได้
  • เปรียบเทียบ agent กับ workflow บนงานเดียวกันด้วยตัวเลข

8 PDF invoices are waiting to be checked. Each must be checked for a correct total and for a match with its purchase order (PO) in the database, then recorded as approved or rejected. You will have the LLM do this through tools, and write the loop that lets it work through several steps.

By the end you will be able to

  • Explain what the model sees of a tool, and who actually runs it
  • Write an agent loop yourself with bind_tools, tool_calls and ToolMessage
  • Design tools that are hard for the model to misuse, and return errors in a form it can act on
  • Compare an agent with a workflow on the same job, in numbers

Option What it does Default

5. Try these in order

  1. Run the same command again. The program reports 8 already checked and makes no LLM calls, because the results are in the database
  2. Run with --reset --mode workflow and compare the time and number of LLM calls with the first run
  3. Run with --reset --max-steps 1 --limit 3 and see what the invoices are recorded as, and what the reason says
  4. Open out/traces.jsonl in the editor and find every tool call for inv_03.pdf

6. Stopping the program, and common errors

Press Ctrl+C to stop. Invoices already checked are in the database. Run again and the program carries on from where it stopped.

Message Cause and fix
ModuleNotFoundError: No module named 'pdfplumber' You have not run uv sync after git pull
0 to check now when you wanted a fresh run The earlier results are still in the database. Add --reset
error: could not start the LLM: ... Run check_setup.py to see which provider has a problem
Several invoices say needs_review The agent finished without saving a verdict. Look for the reason in traces.jsonl, then try a larger --max-steps

7. What the program has that the notebook did not

invoice_agent.en.md explains part by part what the code added to the notebook is for. Read it alongside invoice_agent.py. In short:

In the notebook In invoice_agent.py Why
max_steps only max_steps, and a stop when the model repeats the same tool call with the same arguments A confused model keeps repeating a call until the quota runs out
Trusting that the agent saved a result Checking the database afterwards; recording needs_review if nothing was saved The job is not done until the result is saved
show_trace() prints to the screen Every event written to traces.jsonl You can investigate afterwards why a result came out as it did
A fresh database every time Invoices already checked are skipped Safe to re-run, and it carries on after being stopped
The workflow in a separate cell --mode workflow Compare the two with one command
